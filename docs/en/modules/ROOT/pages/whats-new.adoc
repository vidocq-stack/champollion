= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

* xref:reference.adoc#rest-bindings[`@JsonbPropertyOrder` in generated bindings] — a class or superclass with `@JsonbPropertyOrder` keeps its generated binding, with the runtime's order.
* xref:reference.adoc#rest-bindings[Interface and abstract property types] — a property typed by an interface, an abstract class or `Object` no longer takes its holder out of the generated bindings: its value is mapped by its class, through the binding the processor generates for each implementation compiled with it. An interface with `@JsonbTypeInfo` that is not sealed gets its binding too, unlisted classes going to the runtime.
* xref:reference.adoc#rest-bindings[`@JsonbCreator` without `@JsonbProperty`] — a creator's parameters are named by their own names in the generated binding, as the source declares them; a class file without parameter names says so at build.
* xref:reference.adoc#rest-bindings[Bindings for the entities of a `Response`] — the processor reads the method bodies for the entity given to `Response.ok(…)`, `accepted(…)`, `ResponseBuilder.entity(…)` and `GenericEntity<T>`, binds its type and lists it in `META-INF/champollion/rest-entity-types`, so an endpoint returning a `Response` no longer needs reflection, nor an `opens` found at the first request.
* xref:reference.adoc#rest-bindings[Bindings for the types of a dependency] — the processor lists the types of other jars the resources reach (`META-INF/champollion/dependency-types`), and binds named types with no annotation when given `-Achampollion.jsonb.types`: what Vidocq's `generate` goal needs to bind a library's DTOs in its enriched copy.
* xref:reference.adoc#rest-bindings[Generated bindings with serializers and polymorphism] — a property with a `@JsonbTypeSerializer` or `@JsonbTypeDeserializer` keeps its generated binding, which calls it directly with the context of the calling `Jsonb` (`JsonbBinding` gains `write`/`read` methods that take it). A sealed interface carrying `@JsonbTypeInfo` over records gets a binding that dispatches on the value's record and on the discriminator. A record implementing such an interface now writes its discriminator in its generated binding too, as the runtime does.
* xref:reference.adoc#rest-bindings[Generated bindings with adapters and creators] — a property with a `@JsonbTypeAdapter` keeps its generated binding: the adapter is created once and called directly. A class with a `@JsonbCreator` constructor or factory whose parameters carry `@JsonbProperty` names is created through it, with no reflection. A `@JsonbCreator` factory now wins over a no-argument constructor in the generated binding too, and a JSON `null` for a primitive creator parameter is a `JsonbException`.
* xref:reference.adoc#rest-bindings[Generated bindings with date and number formats, and arrays] — a type a REST resource exchanges keeps its generated binding when it uses `@JsonbDateFormat` or `@JsonbNumberFormat` (on a property, its class or its package) or holds arrays: the binding formats through the runtime's own codec, built once. A JSON-B annotation on a superclass or a package that the generated code does not implement now keeps the runtime mapping, instead of being missed. A record honours the formats and the `@JsonbNillable` of its type and package, and `@JsonbNumberFormat` on a component, as any bean does; a public field is read with its format; a number format is safe across threads.
* xref:reference.adoc#rest-bindings[Generated bindings for plain classes and hierarchies] — the classes a REST resource exchanges get their binding generated even when they are not `final` or extend another class (a `BaseEntity` with an `id`, say): the inherited properties are written first, as the runtime writes them. A type that holds itself (`record Node(List<Node> children)`, `Optional<Entry>` in `Entry`) no longer overflows the runtime's stack.
* xref:reference.adoc#rest-bindings[Bindings for the types REST resources exchange] — the processor generates the JSON-B binding of every record and final class a JAX-RS resource takes or returns, with no annotation: no reflection, and no `opens` for JSON-B. A type it cannot map keeps the runtime, with a compiler note saying why. A generated binding now also reads the values below the root (list elements, map values, members), as it already wrote them.
* xref:reference.adoc#rest-bindings[A module that does not read Champollion keeps the runtime mapping] — the generated bindings compile against `io.vidocq.champollion.jsonb`; a named module that does not read it gets no binding and a compiler note saying so, instead of a compilation error.
* *JSON-B conformance and correctness fixes* — a visibility strategy exposes private fields on read and write (BUG-20261028-04); nested parameterized readers are built and cached by type, not by name (BUG-20261029-09); a property typed by a type variable is read as the type its subclass binds; an inherited accessor is judged by its most specific declaration; a JSON `null` reads as `null` into a `JsonStructure` member and into a container, and `@JsonbNillable` applies to every type; an `@JsonbSubtype` that is not a subtype is rejected on read; the bean members after one read by a `JsonbDeserializer` are read; a `Jsonb` called again while it reads keeps the enclosing read's parser; durations and periods of a bean stay in ISO form; an untyped integer of any size reads as a `BigInteger`; a calendar reads from a date with an offset only; a customised configuration is served by the runtime mapping, not the generated bindings; nested, collection and map values are written through their static binding, and `@JsonbStatic` bindings are found through the context class loader too (Vidocq/vidocq#382); the CDI API is looked up from the bean class's loader; the pooled parser is released on close.
* *Protobuf fixes* — enums decode by their declared number, in static parsers and as map values; the unsigned wrapper types are written and read unsigned; a well-known-type map value is read from its JSON form; nested messages use the top-level JSON field writer; the stream encoder counts the first chunk of a block that overflows its buffer; byte payloads compare by content; the `.proto` parser rejects an unterminated block comment.
* xref:reference.adoc#bound-types-access[A type its module does not open] — when binding fails because the module of a type does not open its package to Champollion, the `JsonbException` says so and gives the `opens` line to add, instead of a bare `Failed to read property` or `ctor failed`.
* xref:internals.adoc[Internals, JSON-P pipeline] — `Jsonb` on byte streams, as a REST layer uses it, costs less. Writing a list of 100 records to an `OutputStream` allocates 8.8 KB instead of 21.6 KB and is about 30 % faster, on par with Jackson: numbers are written without an intermediate string, and a large document borrows a buffer the `Jsonb` keeps instead of growing its own. Reading a small UTF-8 body from an `InputStream` allocates 224 bytes instead of 2,848 and takes about half the time: the body is read whole and parsed as a string with the kept parser, which reuses its tokenizer and remembers the member names it has read. `fromJson` on a `String` or a `Reader` gains the same way. The JSON is the same, byte for byte.
* xref:internals.adoc[Internals, JSON-P pipeline] — the `JsonGenerator` buffers its own output and hands the target `Writer` one write per kilobyte, instead of going through a `BufferedWriter` of 256 characters whose every call took a lock. The output is byte for byte the same; `toJson` to an `OutputStream` or a `String` is cheaper per value.
